# 远程监控服务部署

远程服务负责集中接收各直播电脑的低频状态摘要，并提供：

- `/monitor`：直播间集中监控、版本查看和受限远程维护。
- `/admin`：设备审批、访问管理和内部更新缓存。
- 手机浏览器：经管理员审批后的只读音频与机位监看。
- 企业微信：音频报警、机位超时及恢复通知。
- 内部更新缓存：提前下载 GitHub Release，桌面端优先从直播间服务器更新。

集中监控和手机访问是两套独立能力。即使电脑端关闭手机扫码访问，只要启用了集中监控，电脑仍会向服务器发送必要状态摘要。

## 服务边界

- 容器仅暴露配置的 `8088` 端口，根文件系统只读。
- 容器移除全部 Linux capabilities，并启用 `no-new-privileges`。
- 仅挂载 `data`、`updates` 与只读的 `tls` 目录，不挂载宿主机其他路径。
- 手机端只提供监看，不提供 ATEM 切台控制。
- 二维码只用于提交申请；未经后台审批，浏览器不能读取直播状态。
- 管理命令采用固定白名单。暂停检测需要再次确认，所有执行结果都会写入管理审计记录。
- OBS WebSocket 密码、完整软件配置、GitHub Token 和企业微信 Webhook 不会通过监控接口下发。

## 配置

复制 `remote-server/.env.example` 为 `remote-server/.env`，至少修改管理密码和公网地址：

```dotenv
PORT=8088
PUBLIC_BASE_URL=http://192.168.110.111:8088
ADMIN_PASSWORD=请替换为独立强密码
DATA_DIR=/data
UPDATE_DIR=/updates

UPDATE_SYNC_ENABLED=true
UPDATE_SYNC_INTERVAL_MS=120000
UPDATE_RELEASE_BASE_URLS=
UPDATE_GITHUB_TOKEN=
UPDATE_SYNC_TOKEN=

WECOM_NOTIFY_ENABLED=true
WECOM_WEBHOOK_URL=

TLS_CERT_FILE=
TLS_KEY_FILE=
```

配置说明：

- `PUBLIC_BASE_URL`：二维码和桌面端使用的远程服务地址。公网部署应填写可访问的 HTTPS 地址。
- `UPDATE_SYNC_INTERVAL_MS`：更新缓存轮询周期，默认 2 分钟，服务会合并并发同步，避免重复下载。
- `UPDATE_RELEASE_BASE_URLS`：可选的逗号分隔下载源；留空时按 GitHub Releases、`ghproxy.net`、`gh-proxy.com` 依次尝试。
- `UPDATE_GITHUB_TOKEN`：可选的私有仓库只读 Token，只在服务器直连 GitHub 时使用，不会转发给代理、桌面端或管理接口。
- `UPDATE_SYNC_TOKEN`：可选的 GitHub Actions 发布后预热凭据。
- `WECOM_WEBHOOK_URL`：企业微信“消息推送（原群机器人）”Webhook。
- `TLS_CERT_FILE`、`TLS_KEY_FILE`：服务直接提供 HTTPS 时使用的容器内证书路径。

`.env` 已被 Git 忽略。不要把真实管理密码、GitHub Token 或企业微信 Webhook 写入源码、日志或提交到 GitHub。

## 启动与检查

```bash
cd remote-server
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8088/health
```

默认访问地址：

- 集中监控：`http://192.168.110.111:8088/monitor`
- 管理后台：`http://192.168.110.111:8088/admin`
- 健康检查：`http://192.168.110.111:8088/health`

`/monitor` 与 `/admin` 共用管理员登录会话。公网使用时应配置有效 HTTPS 证书，并在路由器、防火墙或反向代理层限制不必要的入口。

## 集中监控

桌面端会以低频心跳上传必要摘要，包括：

- 直播间名称、电脑标识、客户端版本和系统平台。
- OBS 连接、直播、录制和虚拟摄像头状态。
- 被守护音源的电平、静音阶段与最近一次收到电平数据的时间。
- ATEM 连接、当前机位、机位停留时间和超时状态。
- 更新状态、服务线路、延迟和最后同步时间。

后台不会接收 OBS WebSocket 密码、报警历史或完整设置。管理员可以执行显示软件、重连 OBS、重连 ATEM、检查更新、暂停检测和恢复检测等受限命令。

## 企业微信通知

通知只在状态发生变化时发送：

- 音频进入正式报警。
- 音频恢复。
- 机位停留超时。
- 机位恢复正常。

服务不会按每次心跳重复发送相同状态。短时间内的多台设备事件会批量合并，失败时按退避间隔重试，以降低网络和群消息开销。可在 `/monitor` 顶部查看通知配置和最近错误状态。

## 更新缓存

服务启动后立即检查 Release，之后默认每 2 分钟轮询一次。安装包下载完成并通过 SHA-512 校验后，才会替换版本描述文件，避免客户端取得不完整更新。

缓存仅保留最近两个版本的安装包，多余文件会自动删除。桌面端检查更新时优先使用直播间内部服务器；缓存尚未就绪或不可用时，再按客户端配置尝试其他更新源。

私有 GitHub 仓库可以通过服务器端 `UPDATE_GITHUB_TOKEN` 读取，但客户端本身不持有 Token。切换私有仓库前仍需用真实 Release 做一次完整下载和升级验证。

## 运维建议

- 管理密码不要与 Linux、NAS、OBS 或其他服务共用。
- 仅允许可信办公网、直播网或受控公网入口访问 `8088`。
- 定期备份 `remote-server/data`，其中保存设备、申请、白名单和管理审计记录。
- 定期检查 `/monitor` 中的离线电脑、通知错误和更新缓存状态。
- 更新服务后执行 `docker compose ps` 和健康检查，确认容器状态正常。
